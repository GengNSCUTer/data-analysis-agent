# 连续分析流程约束审查与裁剪

目标：逐层列清在线 SQL 生成与结果复用的约束，用连续问答检查其实际作用，修复有证据的误拦截和状态归属错误。
输入：用户问题、当前 AnalysisState、上次成功结果及 Catalog；输出：有来源的状态更新、正确执行或合理复用的结果。
非目标：新训练、替换模型、跨会话记忆、任意 SQL 语义证明或新增基础设施。
不变量：认证、workspace/版本隔离、表列权限、只读执行、执行资源预算、结果验证与工件归属检查保留。
验收：逐层约束清单；连续排名、下钻、条件修改、失败后续接、结果追问与换图的真实浏览器记录；定位具体失败后加入回归，复验受影响链路。状态属于当前任务，成功结果有独立来源，二者不能混淆。

本轮开始时端口 32016 未监听，先恢复同源网页与 API；只处理这条流程，不扩展后训练或其他页面功能。

## 在线约束清单及取舍

| 步骤 / 代码 | 约束及真实用途 | 本轮取舍 / 局限 |
| --- | --- | --- |
| 登录、bootstrap、conversation_store | 服务端身份、用户/workspace隔离、版本失效、事务并发检查 | 保留；不能以流畅度为由放宽越权与覆盖新消息 |
| budget、analysis_context | 64K请求、48K历史、输出及工具次数/超时预算；完整轮次、后台摘要 | 保留；不参与猜业务条件，也不是六轮截断 |
| semantic_intent | JSON类型、日期、Catalog可见指标/维度、最多4指标、补丁字段有效 | 保留；4指标是当前产品容量，不是业务普适限制。解释器会重试一次格式错误，不回旧关键词路由 |
| AnalysisState | 仅修改本轮指定字段；换分组清旧top_n；失败保留当前范围及上次成功结果独立来源 | 保留；结果展示不能反向覆盖待重试范围 |
| result_reference | 工件归属/版本/完整性、来源ID、维度和排序；唯一最高的并列检查 | 保留有效性检查；删除rank<=8，改按请求从完整工件读取1行，唯一最高读2行，不把全表给模型 |
| result_followup复用 | 原来强制当前任务范围完全等于上次成功结果 | 默认仍相同才可复用；显式请求上一份成功结果有独立目标，不再被当前失败范围挡住；不自动回滚任务 |
| route_semantic_intent | 缺指标/真实歧义、Catalog完整定义、支持维度、归属分摊规则、筛选列来源 | 保留；这是服务能力和口径，不要求用户使用固定句式 |
| top_n_shape_not_supported | 排名只支持单维度且不混时序 | 暂保留并明确是未实现能力；多维/每月Top-N需要新计划语义，不能悄悄当全局Top-N |
| QueryPlan.preflight/from_selection | 分组基数、时间桶、Top-N派生执行预算，禁止不可展示编号 | 保留；有两处调用但后一处负责生成具体预算，不新增额外模型调用。估算偏保守仍可能拒绝本可执行的大组合 |
| CatalogRetriever | 角色过滤，表列/关联路径与指标上下文有界（在线6表） | 保留；是实际提供给SQL模型的信息，超容量不得丢指标后假装完整 |
| filter_source_resolver | 多编码维度用reader参数化EXISTS识别值来源 | 保留；不是未知值闸门，未知值可查空；不实现任意中文类目翻译 |
| plan_sql_guard筛选与关联 | AST识别实际参与指标的条件，发现丢筛选、错误列、非唯一键关联放大 | 保留；只覆盖已实现SQL形式，不证明任意等价SQL或指标公式。需持续用合法别名/CTE/IN/EXISTS正向测试防误拦 |
| plan_sql_guard排名LIMIT | 原来要求模型写LIMIT，否则模型修复 | 在线aggregate删除这项重复检查；执行策略已按服务端Top-N重写外层LIMIT。历史离线协议不改 |
| plan_sql_guard归因 | 支付分摊等计划要求出现在候选SQL | 保留但只是有限提示/检查，不是完整数学证明；不为每个公式再加字符串黑名单 |
| SqlPolicy | 单只读语句、AST对象/函数白名单、敏感字段、限制顶层LIMIT/OFFSET | 保留；与计划业务一致性不同。COUNT(*)是聚合，不等于SELECT * |
| PostgreSQL runner | 独立reader、只读事务、超时、行数+1/字节预算 | 保留；最后执行安全，不能证明业务口径正确 |
| ResultValidator | 指标列/合理数值、完整结果、时间桶/范围等，缺形状列降级展示 | 保留；不负责自然语言理解。空结果/NULL不伪造可信业务数值 |
| 一次SQL修复 | 仅候选/执行类可修复错误，失败不无限循环 | 保留；日志区分候选被拒与数据库执行失败。不能把校验器不足推给用户补信息 |
| ChartContract | 图类型、列类型/数量、最多200绘图行；服务端确定性生成 | 保留；绘图失败不应否定已验证数据。复用图表按工件自己的范围构建，而非当前失败范围 |
| 摘要/前端/工件 | 模型8行/1200字符，UI200行，完整CSV分页/下载检查归属 | 保留各自职责；八行只限制模型摘要，不限制服务端引用第十行 |
| 结果解释数字检查 | 未在可信摘要出现的数字触发摘要复述 | 本轮记录局限：会把列表序号、格式化数字也视为新数字，且不验证因果语义；不能直接删掉防编造措施，后续单独设计结果解释证据方式 |

## 连续对话观察

九轮正常链路：最高销售额州 → 当地品类 → 前十 → 前五 → 只换图 → 改销量 → 改州RJ → 撤销州 → 解释结果。
另两组：前十结果引用第十名；查询范围变更失败（受控状态夹具）→ 明确展示先前成功结果 → 重试失败范围。
逐轮记录语义输出、状态、QueryPlan、策略/SQL尝试、修复、结果合同与耗时；原始SQL只在仓库外受限证据中，查询结果与独立reader计算核对。
前测复现第十名无法解析、失败后旧图被拒，另发现缺失品类翻译导致名称为nan。翻译使用COALESCE回退原名，不新增查询拦截；真正NULL品类保留NULL组。

## 本轮裁剪后的联合验收（2026-10-17）

三组真实流程均使用同一个同源服务、真实 SSE、PostgreSQL reader 和 Playwright：

1. **九轮连续分析**：最高州 → 州内品类 → 前十 → 前五 → 只换图 → 改指标 → 改州 → 撤销州 → 解释结果。9/9 完成；第 1–4、6–8 轮各有一次 SQL 审计，第 5、9 轮明确走 `result_followup`，SQL 调用数为 0。
2. **摘要之外的第十名引用**：从已验证完整 CSV 按游标读取第 10 行；模型上下文仍只保留 8 行，服务端没有把完整表送入模型。2/2 完成。
3. **失败范围与旧结果并存**：受控地让当前前五查询失败，再明确要求展示上一份成功结果，之后重试当前范围。旧图复用不改变失败任务的 `top_n`，重试仍按当前范围执行。3/3 完成，其中旧结果复用 SQL 调用数为 0。

逐轮证据位于仓库外 `evals/analysis-memory-phase5-20261016/flow-{continuous,rank-reference,failed-scope}/`，每轮记录语义意图、路由、状态、QueryPlan、SQL 审计、结果合同、复用决定和终止原因；原始 SQL 只存在受限审计目录。确定性回归为 **337 passed**，M1–M4 网页回归在主端口为 **5 passed**。

这次真实失败暴露了四个实际的误拦截或职责混淆，已按最小范围裁剪：

| 发现 | 调整 | 保留的边界 |
| --- | --- | --- |
| `rank <= 8` 把模型摘要展示预算误当成实体引用上限 | 引用从归属已验证的完整 CSV 按需读目标行；唯一最高额外读相邻行检查并列 | workspace、用户、版本、CSV checksum 和排序方向仍必须一致 |
| 当前失败任务的范围挡住了用户明确要求的上一份成功结果 | `result_target=last_successful_result` 与 `current_task` 分开；旧结果解释/绘图不回滚当前失败状态 | 只有用户明确指向上一份成功结果才复用，不能用旧数字回答当前失败查询 |
| 在线聚合计划要求模型重复写外层 `LIMIT`，造成无意义修复 | Top-N 由服务端执行策略统一生成，删除在线重复检查 | SqlPolicy、只读角色、行数/字节/超时和 ResultValidator 仍执行 |
| 只换图又重新构建 QueryPlan，缺失筛选维度时在已验证 CSV 之前被拦截 | 图表合同直接从已验证 artifact 的结果形状构建，只做图列/类型/空值/重复键检查 | 图表仍最多 200 行，不能展示未声明字段或在展示层重新聚合 |

另外，英文品类名称缺失时改为 `COALESCE(英文名, 原始名)`，QueryPlan 提示禁止未请求地删除真实 `NULL` 分组；计划拒绝和修复拒绝现在在执行前写入受限 SQL 审计。没有增加 hash、表、关键词路由或兼容接口。

仍有意保留的能力边界：多维/按时间的 Top-N 尚未实现；结果解释中的数字检查仍可能把列表序号当新数字；提供方超时会按失败记录。这些是下一项独立任务，不通过放宽安全约束解决。
