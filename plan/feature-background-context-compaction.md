# 当前任务后台摘要与 token 预算优化

任务卡：改善当前任务长对话连续性，按 token 选择完整历史，回答后批量压缩并持久化。
输入为所属会话原文、当前 AnalysisState、已有摘要；输出为连续上下文、可重启续接的摘要及测试证据。
SQL 条件仍只使用受控状态和可信工件。范围不含跨任务召回、长期记忆、训练和新队列服务。

实施顺序：统一 RequestBudget 与完整轮次游标读取；接入后台任务及事务内摘要专用写入；
补充摘要质量、失败无缺口、并发、重启和真实浏览器验收。默认总预算 64K、历史 48K，
原文 24K 触发、压缩后保留约 16K；摘要目标 2K/上限 4K、输入 24K、超时 60 秒。
后台每会话一个任务，全服务两并发；摘要失败不推进覆盖位置，源消息与版本失效时不写回。

验收：确定性异步/项目数据库回归与真实浏览器长对话；证据放仓库外，最终记录写入 PROJECT.md。

## 实现与验收记录

三阶段均已实现。预算统一在 `RequestBudget`；`get_turn_range()` 分页读取完整轮次，
`AnalysisContextBuilder.build()` 读取已有摘要和连续原文，语义解释与 Agent 共用同一范围。
`schedule()` 在本轮持久化后调度隔离计量的后台任务；`save_history_summary()` 在行锁事务内
核对归属、任务/版本、旧覆盖位置及源消息主键，只更新派生摘要。普通写入保留数据库最新摘要。
完整请求超预算时等待或尝试一次同步压缩，失败明确报上下文不足，不静默截去原文。

摘要提示保留目标、纠正、待办和展示偏好，禁止把原始 SQL、工具返回或表格写入摘要。
超长轮次分片形成临时摘要，整轮成功后才提交；服务关闭取消未完成任务，下一次请求可续接。
64K 为服务配置预算；本地 tokenizer 计数仍按估算方式记录，不声称等于供应商实际窗口。

确定性测试覆盖 45 个短轮次分页不提前压缩、24K/16K 触发、失败原文保留、超长分片、
两个后台并发、追加消息和清空/编辑/版本失效竞态、工具配对、完整请求超限后重建。
真实浏览器联合矩阵 9 项通过，额外摘要失败/实际服务重启用例 1 项通过。
最终主端口长历史与排名引用复验 2 项通过；最新确定性回归两批合计 281 项通过。
长历史由持久化夹具注入，随后使用真实模型、浏览器和数据库验证两次增量压缩；
没有把重复测试文本当作任意自然语言业务准确率证据。

证据：仓库外 `evals/background-context-compaction/final/`、`restart-final/`、`main-final/`。
记录包含摘要覆盖范围、调用次数、压缩前后 token、未处理消息量、失败类型和浏览器响应时间。
