# Catalog 维度组合筛选与连续下钻

目标：解除只允许单个客户州筛选的业务限制，让可见 Catalog 维度的等值条件贯穿意图、QueryPlan、SQL 生成、执行检查和工件范围。
输入：当前任务补丁、已验证实体引用、Catalog 表列；输出：按确认条件执行并能继续修改范围的结果。
本轮不改模型、训练、摘要、历史任务召回、结果复用目标选择或多维 Top-N。

不变量：权限、表列白名单、敏感字段、只读角色和执行预算保留；筛选值是数据，不拼成 SQL 指令。原始 Olist/多 schema 离线协议保留。业务检查应识别真实谓词，不能因列名/字面量仅在注释、投影或无效分支出现就判为已筛选，也不能限定用户句式。

实现：Catalog 维度来源生成结构化计划条件；支持多个不同维度的等值条件取交集；允许规范值和已声明显示列来源；检查 SQL AST 中有效查询路径的条件。无法访问/表达的维度明确说明能力不足，不伪装成用户缺信息。
验收：组合筛选、字段别名/CTE/英文品类、条件增删改的正向测试；漏筛选、错字段、无效条件、未用 CTE、越权字段的反向测试；真实浏览器重放三问及不同指标/维度，独立 reader 数值核对。

真实测试补充：英文显示值被用于原始编码列会查空，因此在 SQL 生成前通过 reader 的参数化 EXISTS 确认可用值来源；未知值不作为语言拦截。已固定所有分组维度的查询最多一组，不要求冗余 LIMIT。数值对照发现商品行序号去重错误，补充 Catalog 复合主键与计数说明，不增加新的字符串公式闸门。验收结果写入 PROJECT.md。

主端口复验补充：明细通过非唯一品类名重新关联原始商品表，使 GMV 放大约三千倍。计划携带 Catalog 已有多对一关系并检查可追溯原始维度表关联键；普通主键、CTE 别名、翻译表和聚合结果间关联有正向测试。该真实失败不能由只读权限或结果列类型检查发现，不能把执行成功当作数值正确。
