# 文档生命周期地图 v1

**状态：** 当前文档治理入口（2026-09-21）。

本项目同时包含产品运行时、数据合同、后训练实验和学习材料。它们的证据等级和读者不同，不能通过把所有内容合并成一篇长文档来解决混乱。本地图规定每类内容的唯一当前入口、历史保留方式和更新规则。

## 当前入口

| 内容 | 唯一当前入口 | 更新规则 |
| --- | --- | --- |
| 项目目标、已完成能力、当前实验事实和下一步 | [`PROJECT.md`](../../PROJECT.md) | 只记录可回链到代码、测试或仓库外证据的事实；历史事实不改写，追加更正记录。 |
| 本地文档导航与生命周期 | [`docs/README.md`](../README.md) | 只维护入口、状态和链接，不复制长篇正文。 |
| 产品架构、运行时合同和缺口 | [`docs/architecture/`](.) | 一个主题一份当前设计；已完成的计划在正文头部标明 `Complete`，不再把“未实现”留在现状描述中。 |
| 后训练数据、实验和学习 | [`docs/post-training/README.md`](../post-training/README.md) | `data/` 是合同，`experiments/` 是事实，`learning/` 是学习；三者不互相代替。 |
| 周计划与阶段任务 | [`plan/`](../../plan) | 计划完成后保留原文件作为决策证据，并在状态字段和 `PROJECT.md` 中标记完成。 |

## 归档与删除规则

历史实验报告、数据来源、模型结果和失败证据具有不可替代的溯源价值，即使不再是当前结论也保留原文，并在文件头标注“历史/被替代”。不通过文件名猜测过时，不批量删除 `verification-*`、`post-training-*` 或日期报告。

根目录的 `post-training-*.md` 兼容入口只保留短跳转说明，不再新增正文；完整内容以 `docs/post-training/` 为准。只有满足以下条件才允许物理删除文件：没有代码/文档引用、内容已逐段迁移、对应证据没有唯一性、并且删除后通过 Markdown 链接检查。物理移动或删除必须单独提交，不能混入功能开发。

## 当前状态标记

- `Current`：当前规范或当前事实入口。
- `Proposed`：设计已讨论但尚未实现，不能当作产品能力。
- `Complete`：代码和定向测试已完成；仍须区分测试覆盖范围和未验证能力。
- `Historical`：保留证据，不用于当前配置、训练或评测结论。

文档审阅时先看状态和证据路径，再看正文。若当前文档与旧报告冲突，以最新版本合同、测试和 `PROJECT.md` 的追加事实为准。
