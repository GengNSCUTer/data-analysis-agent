## 2. 这次实际验证了什么

连续修改的10个任务均为4—5轮完整对话；两库都覆盖“最高州→该州品类前十→改前五→
横向图”，以及年份替换、取消时间/州筛选、取消分组、切换指标、用户更正口径和只换图。
41轮的CSV/状态/正文检查均通过。Olist SP州GMV为5,163,867.22 BRL，后续品类下钻保留SP；
TheLook Guangdong最高州成交额145,365.17，后续前五仍属于该州。

历史类已完整通过两库的“新建订单任务后回看旧销售额排行榜差额”，差额分别为
3,352,243.80 BRL及28,890.81，当前订单任务未覆盖，差额计算0SQL。
TheLook全年月表→第四季度→页面刷新→回看全年128.61万也通过，季度状态保持。
Olist相同回看正文610.85万正确，但有下述分析记录差异。

| 检查项 | 实际证据 |
| --- | --- |
| 数值与形状 | 71轮中54轮独立对照正确；1轮实际SQL结果错误；16轮API阻断，未获得有效新结果。其中4轮还能下载旧CSV，不能算当前查询成功 |
| 图表 | 13轮明确要求绘图；11份实际图表重放、逐系列与独立参考核对通过；2轮因API阻断无图，保留失败 |
| 历史/本地复用 | `LOCAL_COMPUTE`10轮、`DIRECT_REUSE`7轮，17轮均0SQL；0SQL不替代数值或业务正确性 |
| SQL执行 | 38次实际SQL审计均allowed，未记录数据库超时；TheLook错误分组同样被allowed，说明安全通过不证明业务正确 |
| 文字解释 | 48轮accepted；5轮只换图；2轮unverified；16轮语义理解阶段失败。解释共35次复核、1次修订，无解释超时；其中1次解释请求API错误 |

上述延迟包括提供方等待，不据此宣称固定提速。已有评测器回归`tests/test_agent_business_tasks.py`
为**33 passed**；本轮只更新验收文档，没有重跑与本任务无关的全仓库测试。

## 3. 七项未通过，分别是什么原因

| 任务 | 触发问题/轮次 | 结论 |
| --- | --- | --- |
| o-history-2 | 第3轮：“回看刚才全年十二个月，全年合计多少？保持当前第四季度分析。” | 回答6,108,492.27 BRL正确，可信证据已有`statistics.gmv.sum_of_returned_rows`同值，0SQL且保持Q4；但意图选择overview，未生成评测要求的独立`analyses.sum`，保留`analysis_missing:sum`。这是证据表示/验收要求差异，不是金额或状态错误 |
| o-history-3 | 先问“全部时间商品成交额最高的十个州”，再问所有州总额与前十区别 | 首轮CSV正确、解释请求API失败；后两轮语义理解402，未执行总体补查，不认定Top-N防护已完成验证 |
| t-history-3 | 第1轮：“客户州已完成成交额前十名。” | **真实业务SQL错误**：按user_id预聚合，外层按州和个人金额分组，未再次按州求SUM，产生同一州多行，金额最高仅约1,312.57，正确州额应145,365.17。独立CSV州/数值均失败；解释重复广东，经一次修订仍未核验，错误正文未发布，但错误表格已通过现有结果合同。后两轮又遇402 |
| o-history-4 | 2017月GMV→明确重新查询→旧结果画折线 | 三轮语义理解均402；无有效查询或工件；最后等不到图表是上游失败的后果 |
| t-history-4 | 2023月成交额→明确重新查询→画折线 | 同上，三轮API阻断；不能判断刷新是否正确绕过缓存 |
| o-history-5 | 2017月客单价→全年客单价→解释不能平均月均值 | 三轮API阻断，没有实际执行月/年SQL；不是本轮证明客单价算错 |
| t-history-5 | 2023月平均完成订单金额→全年值→解释非可加 | 同上，三轮API阻断，未验证全年加权金额链路 |

两服务日志首次402分别约为13:03:16.950与13:03:17.155，共33次API错误观测影响17轮：
1轮发生在结果解释，16轮发生在语义理解。应先检查硅基流动账号支付/可用额度；本轮未充值、
改密钥、切模型或反复探测。前端把这些情况显示为“需要补充信息/请稍后重试”，容易让人
以为问题不够明确，也应作为错误提示改进项，而非用户上下文丢失的证据。
