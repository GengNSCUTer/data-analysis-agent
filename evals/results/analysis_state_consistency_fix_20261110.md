# 当前分析修改一致性修复验收

本轮只修复“修改当前分析后，文字、表格/CSV与状态不一致”。原60项和12项最终成绩保留，
本次复验为在线开发验收，不合并为新的总体准确率。不改训练、SQL安全规则或解释核验。

## 原因与实现

原语义提示混淆了两个判断：是否修改当前分析，以及能否不查数据库而复用CSV。模型会将
“从刚才结果只看第一季度、不重查”理解成`keep + rows`，正文只解释三行，但全年表和状态
继续生效。另一方面，无补丁的`update_task`可把默认空字段应用到状态；州筛选也可能在
下一轮误变成州分组，或总体查询仍保留州列。

`semantic_intent.py`明确任务动作与取数方式独立：修改当前范围提供补丁或完整回答范围；
临时补看/解释/换图及明确保持当前任务的回看才只读。结构冲突用已有的一次纠错；未知或
越权Catalog对象仍不重试。不按中文关键词决定准入，也不允许默认空值清除未修改条件。

真实复验发现只加提示仍不稳定，重新生成整套意图的确认也存在非法结构与旧分类锚定。
最终仅对“选当前工件子集却声明keep”的疑点，在现有最多两次意图调用内独立确认，输出
已有`StatePatch`。非空补丁变成当前任务修改，空补丁保留只读；不把旧分类喂回确认，也不
重新生成整个意图。改变范围后丢弃针对旧表的行号读取，非位置计算可保留。补丁仍经过
正常范围合并、Catalog验证和覆盖证明，不授权SQL。失败不应用未确认提案。

`chat_runtime.py`让当前任务的复用结果明确激活任务，保留现有独立派生CSV与同事务提交，
清掉已解决的澄清信息，记录`updates_current_task`并标注“当前分析 · 本地计算”。只读历史
视图和当前任务分开，刚激活的结果不会再次被误作历史焦点。失败提交不发布新表或正文，
派生工件不延长原快照期限。没有增加表、hash、冻结协议或另起编排层。

评测入口额外核对完成状态与当前工件的指标、分组、筛选、日期、粒度、排名及计划结果列；
保留原有独立SQL、CSV数值容差与严格任务判定。失败的待查询状态允许保留上一份成功工件，
不会把旧结果当成本轮成功。
