## 根因与修改

| 根因 | 当前修改 | 不放宽的边界 |
| --- | --- | --- |
| `formatted_metrics`父引用被转成带空下标的数组路径，抛`ValueError` | 父/叶引用统一映射到原始样本，非法路径变成一次纠正反馈 | 显示字符串不能证明金额，仍核对原值、实体与单位 |
| “6种事件”“12个月”被当作业务金额；正确逐月列表仍触发无意义复核 | 分类数与金额分开；明确月份/数值逐对验证；完整合计范围对照半开日期 | 数字池不能证明配对，错月、换年、月值冒充全年保留反例 |
| 前置比较被反向解释；“12月达到峰值，较10月……”中的达到误当到 | 按实际比较连接词及基期核对具体两行的有符号变化率 | 反方向不能沿用原增长率；百分点与相对百分比仍分开 |
| `judgment=false`被当作全年没有上涨，复核改错正确回答 | 改为`monotonicity.predicate/verdict`，与`endpoints`分开 | 逐期增长、首末变化是两种结论，不宣称统计趋势获得完整证明 |
| Top-N内最小值被称为全业务最低 | 显式总体最低声明要求限定榜单范围，明确年月极值对照真实行 | 不扩张Top-N完整性，不从样本猜总体 |
| 只选择历史来源但漏交差额操作 | 意图提示明确来源与计算分开；初稿可请求既有受控计算，再用唯一修订机会回答 | 仅本次完整证据；非可加求和、部分样本、未知列、二次计算拒绝；0新增SQL工具 |
| 解释支付与GMV区别时只有支付指标定义 | 按现有角色过滤Catalog补充问题涉及的定义 | 不增加观测指标/结果列，不把定义变成数值事实 |
| 全年单值SQL仍输出上轮月份，执行后才失败 | 最终SELECT列在计划对照时反馈给已有一次SQL修正 | 内部CTE键不误伤，ResultValidator/Policy/reader职责保留 |
| SQL为展示而ROUND，完整CSV丢精度 | 在线系统提示明确查询保留原精度，展示层格式化 | 不改离线冻结Prompt、不放宽独立CSV比较容差；提示不等于任意SQL精度证明 |
| SSE内部错误卡未被测试器计失败 | 任意error状态卡都计运行失败 | 不靠数据库审计completed掩盖前端错误 |

继续由模型自由组织正文，不恢复业务句式模板。解释总预算90秒、初稿60秒、复核/修订各30秒，
最多一次修订；语义复核使用512tokens、最多3条短问题。失败仍隐藏未核验正文，保留可信数据。
本轮在真实草稿中观察到复核“31应为31”和常见译名误判；缩短提示不能单独解决，故对能
明确证明的月份、范围及极值减少多余复核，无法证明的对应、换算、排名、因果仍需复核。
