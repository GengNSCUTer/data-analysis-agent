## 当前路由器能解决什么、不能解决什么

### 能解决

点名了指标、又给出 2017 或 2018 这种日历年份的查库句，87/87 全部放行，指标也没有对错。各州、各月、各品类、各支付方式这几种分组都在里面。
本月、最近 30 天、今年这三句相对时间，57/57 都停在澄清，指标仍然记着，SQL 没有打开。路由器不会把「本月」猜成某一天。
帮助 6/6，结果追问 13/13。有上一轮可信摘要时解释旧数字；没有摘要时要求用户说明是哪一轮；点名 GMV 再按州或品类拆开查，会走新查询。
支付金额、光说金额、光说订单、哪个地区表现最好，16/16 都没有猜成 GMV 或其他指标。
删除、修改、插入、导出原始、预测、运行 Python 这些词出现时会拒绝。最火、热销、订单最多、取消订单最多会落到合同里写好的指标。
「把/将……改成/变为/设为……」按句法框架拒绝写库，不靠往拒绝词表里补「改成」。点名了指标也不会因此打开 SQL。
定义和建议先去掉已经对上的指标别名，再判剩余句子。别名里的「平均、金额、数量」不会把「是什么」和「如何提升」推进查库。
「各州卖得最好的货」按排名维估行数，不再用 27×73 把已经对上的商品件数整句拦住。
只要标准答案点了指标，这 235/235 题的指标都对上了。剩下的不一致主要是拒绝原因，不是把 GMV 认成别的指标。

### 不能解决

「预测下个月的系统表」「运行 Python 计算 information_schema」这 4 题仍然拒绝，SQL 没开。系统表和 information_schema 的检查排在预测、跑 Python 前面，所以拒绝原因记成未授权，而不是不支持的能力。

### 后续可以改哪里

系统表和预测叠在同一句时，可以继续拒绝，并在卡片上同时写明未授权和不支持。这 4 题没有打开 SQL，优先级低于该不该查库。
不为凑满分再加词。成绩变化只走记分卡 diff，不改标准答案。

## 这些数字不能当成什么

证据类型一致只说明路由放行、澄清、解释或拒绝是否和句式合同相同。
它不证明 SQL 能执行，也不证明查询结果在业务上正确。
标注是作者按 Catalog 合同写成的，不是独立第三方标注，也不是在线语义准确率。
